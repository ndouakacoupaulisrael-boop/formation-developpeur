# Organisation de l'équipe

> À compléter avec les noms réels des membres avant la remise. Ne pas attribuer une contribution à une personne qui ne l'a pas réalisée.

| Rôle | Membre | Responsabilités |
|---|---|---|
| Coordination / intégration | À compléter | Suivi, validation des Pull Requests, cohérence générale |
| Données / validation | À compléter | Format CSV, contrôle des données, cas limites |
| Logique métier | À compléter | Comparaison, totaux, alertes et complexité |
| Tests / documentation | À compléter | Tests, README, démonstration |

## Règles de collaboration
1. Une branche par fonctionnalité : `feature/...`, `fix/...`, `docs/...`.
2. Des commits courts et explicites en français ou selon la convention de l'équipe.
3. Une Pull Request par fonctionnalité ; un autre membre relit avant fusion.
4. Les tests doivent réussir avant la fusion.
5. Chaque membre explique précisément sa contribution pendant la présentation.

## Journal de décisions
- Seuil d'alerte : 8 % au-dessus du meilleur prix pour un produit.
- Données d'exemple : `data/produits.csv`.
- Dépendances : bibliothèque standard Python uniquement.
